Why 4x?

Single-agent coding is fast but fragile. 4x splits the loop so each role has a focused job, limited scope, and no access to the others' reasoning.

Role Isolation

The Coder never judges its own work. The Reviewer is adversarial by design. No self-review bias.

Crash-Resistant

Everything lives in .4x/ files. Session dies, machine reboots — run picks up exactly where it stopped.

LLM-Agnostic

Switch between Claude, Gemini, Codex, or mix them per role. File-based protocol, no vendor lock-in.

Batch Mode

Dependency-aware scheduling. Queue dozens of features overnight, review them in the morning.

How It Works

Spec & acceptance criteria

Verify against criteria

If review or test fails, the loop iterates automatically.

Quick Start

# Install
$ brew install ggwhite/tap/4x
# Initialize in your project
$ 4x init
# Create a feature
$ 4x new "User authentication with OAuth2"
# Run the AI development loop
$ 4x run F001
# Watch it live
$ 4x live
Also available via: go install github.com/ggwhite/4x/cmd/4x@latest curl -sSfL .../install.sh | sh

Configuration

Monorepo or multi-repo. Per-role models and instructions. Inject your coding standards, architecture docs, and project rules.

{
  "project": {
    "name": "my-project",
    "language": "go",
    "build": ["make build"],
    "test":  ["make test"],
    "lint":  ["make lint"],
    "docs":  ["docs/architecture/overview.md"],
    "rules": ["always use structured logging"],
    "includes": ["docs/coding-standards.md"]
  },
  "runners": {
    "claude": { "command": "claude", "model": "opus" }
  },
  "default_runner": "claude"
}
{
  "project": { "name": "my-platform" },
  "workspace": {
    "repos": {
      "core":    { "path": "core",    "hub": true },
      "gateway": { "path": "gateway" },
      "admin":   { "path": "admin" },
      "web":     { "path": "web" }
    }
  },
  "runners": {
    "claude": { "command": "claude", "model": "opus" },
    "gemini": { "command": "gemini" }
  },
  "default_runner": "claude",
  "isolation": "worktree"
}
// Per-role model, instructions, and context — tailor each AI agent to your project
{
  "roles": {
    "designer": {
      "model": "opus",
      "instructions": [
        "all specs must define gRPC proto changes before implementation",
        "acceptance criteria must include load test thresholds",
        "always consider backward compatibility with existing clients"
      ],
      "includes": [
        "docs/architecture/service-map.md",
        "docs/api/proto-conventions.md"
      ]
    },
    "coder": {
      "model": "sonnet",
      "instructions": [
        "use dependency injection via dig container",
        "all DB queries must go through repository layer",
        "structured logging only — no fmt.Println",
        "new endpoints must have OpenAPI annotations"
      ],
      "includes": [
        "docs/coding-standards.md",
        "docs/error-handling.md"
      ]
    },
    "reviewer": {
      "model": "sonnet",
      "instructions": [
        "check for SQL injection, XSS, and auth bypass",
        "verify all money calculations use decimal, not float",
        "flag any direct DB access outside repository layer"
      ]
    },
    "tester": {
      "model": "sonnet",
      "instructions": [
        "integration tests must use testcontainers",
        "test concurrent access for all shared state"
      ],
      "screenshot_dir": ".4x/e2e/{feature-id}/screenshot/"
    },
    "deep-reviewer": {
      "model": "opus",
      "parallel_reviewers": 3,
      "max_fix_rounds": 2,
      "includes": [
        "docs/architecture/overview.md",
        "docs/architecture/data-flow.md",
        "docs/security/threat-model.md"
      ]
    }
  }
}
