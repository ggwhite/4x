The Loop

四個角色，四種視角，
零自我審查。

Design
01

釐清需求、限制、風險與驗收標準。
Designer 不寫程式碼。

Code
02

根據規格實作。看不到 Reviewer 的回饋，不替自己批准。

Review
03

對抗式審查：範圍越界？設計偏離？錯誤處理不足？

Test
04

依照事前標準驗證，留下可檢查證據，不信 Coder 自述。

Design → Code → Review → Test → Deep Review → Done
Review 或 Test 失敗？自動進入 amending 回圈重來。
人類在最終 Accept 階段把關，而不是每一步都盯。
同一個 feature，分成四種責任。 4x run --runner claude

04/06
Safety

安全邊界寫在 Go 裡，
不是寫在 prompt 裡。

不靠 AI 自律，用 CLI 工具硬性強制每一條邊界。

狀態機 init → designing → coding → reviewing → testing → done，禁止亂跳。
Scope Lock 改的檔案必須在宣告的 repos 範圍內，越界直接擋。
Baseline Snapshot Coding 前快照，隨時可 rollback 到乾淨狀態。
Evidence Gate Tester 必須產出 verify.json + test-report，不接受空口無憑。
Dependency Gate 前置 feature 未完成？這個 feature 不准開始。
Human Gate AI 跑完全部 phase 後，pending-review 等人類最終審核。
Crash Recovery + Transient Retry Runner 中斷自動恢復、API 暫態錯誤自動 backoff 重試。
網路抖一下不會毀掉整個 batch run。
AI 負責判斷，CLI 負責邊界。 .4x/ protocol

05/06
Self-Evolution

4x 會從自己的
失敗中學習。

L1
Retro Learnings 每輪結束後回顧，自動調整下一輪的 prompt template。越跑越準。
L2
History Mining 從失敗 run、escalation、反覆 FAIL pattern 中挖掘改進訊號。
L3
Feature Enrichment 自動發現的改進項目，補齊 subtask、scope、priority 後直接排入 pipeline。
L4
Value Gate + Scope Guard ROI 評估 + anti-hack 防護。改自己核心時額外保護，防止越改越壞。
L5
Evolve Driver 一條指令啟動持續自我改進迴路：挖掘 → 評估 → 實作 → 驗證 → 部署。
AI 不只是執行工程流程——它從自己的失敗中學習，持續迭代，越跑越強。
用 4x evolve 啟動自我改進迴路 4x evolve
